Overview

ARGUS (Advanced Records & Geospatial Unified Surveillance) is a full-stack telecom forensics platform for law enforcement investigators. It ingests CDR (Call Detail Records) and IPDR (IP Data Records), reconstructs communication sessions and movement, and surfaces investigative leads through a spatiotemporal inference engine and an optional local AI assistant.

The system is designed for air-gapped deployment: it runs entirely offline, ships as a self-contained Windows installer, and stores every case in a local PostgreSQL (or SQLite fallback) database. No data ever leaves the machine unless the operator exports it.

Backend Python 3 · FastAPI · 26 routers · 24 services · 15 SQLAlchemy models
Frontend 47 native ES modules, no build toolchain — loads directly in the browser
Testing 242 backend tests across 32 suites, unittest-based

Quick Start

Windows installer (recommended for investigators)

Download the ARGUS installer from the GitHub releases page and run it. The installer bundles the Python runtime, all dependencies, and the frontend — no separate Python install, no internet connection required. On first launch, ARGUS opens in your default browser at http://localhost:8000.

First login — the app bootstraps a default admin account from environment variables on first start. Change the password immediately from the Admin tab.

Development setup

cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1        # Windows
# source .venv/bin/activate       # Linux/macOS

pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

Then open http://localhost:8000. SQLite is used automatically if no DATABASE_URL is configured — no database setup needed for local development.

Generate sample data

cd backend
python scripts/generate_sample_data.py

Produces deterministic (seeded) sample CSVs — 60 towers, 1,200 CDR and 1,800 IPDR records across 10 Indian cities — in backend/sample_data/, ready to upload.

Case Model

Every CDR and IPDR record belongs to a case. Investigators create, switch between, and reset cases independently; uploading data always targets the currently active case. Two things are deliberately global, not case-scoped:

  • Tower repository — auto-harvested from every upload across every case, so tower coordinates learned in one case benefit all others. Upserts never clobber existing coordinates.
  • Subject intel tags & suspect groups — a free-text tag or watchlist entry on a phone number/IP follows that identifier into every case it appears in, so outside intelligence on a reoffender travels with them.

Cross-case linking (see Features) is how the system surfaces when a subject from the current case has also appeared elsewhere — matched by number, IMEI, IMSI, or (low-confidence) IP.

Architecture

Three layers, each replaceable independently:

01
Data Layer

PostgreSQL primary with automatic SQLite fallback. SQLAlchemy ORM across 15 models. Optional Redis cache tier and Celery workers for background jobs. Trigram/FTS5-accelerated search, opt-in table partitioning for very large cases.

02
Analysis Layer

FastAPI application: 26 routers under backend/app/api/, 24 services under backend/app/services/ holding all business logic. Pandas for ingestion/aggregation, NetworkX for graph analytics. An in-process event bus decouples uploads from analytics materialisation — a case-import event triggers an async re-materialise job rather than blocking the upload response.

03
Intelligence Layer

The spatiotemporal inference engine (movement, co-presence, behavioural, identity, VPN signals) runs as pure functions over record iterables — unit-testable without a database. A fine-tuned local LLM (via Ollama, optional) powers the AI Insights tab; no data leaves the machine.

Service Attribution Engine

ARGUS classifies IPDR sessions to a provider and service fully offline — no external lookups, no telemetry. Two engines (server-side Python, client-side JavaScript) share one knowledge base so results never diverge between the API and the UI.

Two layers

  1. Infrastructure (IP) — longest-prefix CIDR match against 62 curated providers (Meta, Google, Cloudflare, Indian carriers, hosting providers, VPN/anonymisation networks, …). The destination IP names the contacted service; the subject's own IP is only ever used to identify their access network (carrier), never as a content label — misattributing a session merely originating from a cloud IP as that provider is a documented failure mode this engine avoids.
  2. Port + protocol — a shared 264-rule table (250 exact ports + 12 range bands) covering everything from WhatsApp STUN to database ports to BitTorrent, with behavioural fingerprinting (session duration, byte symmetry, traffic pattern) layered on top for a confidence score.

Single source of truth

Both the backend (service_attribution_service.py) and frontend (services/attribution.js) engines load the same attribution_data.json — providers, CIDR ranges, and the full port table. Editing the JSON and regenerating the frontend copy keeps both engines byte-for-byte aligned:

cd backend
python scripts/gen_attribution_js.py

Security & Sessions

PBKDF2-HMAC-SHA256210,000 iterations, random 16-byte salt per password
48-byte tokenssecrets.token_urlsafe(48), HttpOnly cookie — never readable by JavaScript
7-day sliding TTLEvery authenticated request extends expires_at; configurable via AUTH_SESSION_TTL_HOURS

Frontend session hardening

  • AFK auto-logout — a 3-stage idle chain: Active → Idle (2 min) → Expiring (9 min, pulsing warning) → logged out at 10 minutes of inactivity, tracked across mouse/keyboard/scroll/touch events.
  • Health check — pings GET /auth/me every 5 minutes; a 401 triggers immediate logout if the session was revoked elsewhere.
  • Multi-session tracking — list every active session, revoke one or all ("logout everywhere").

Chain of custody

Every meaningful action — login, upload, export, dossier generation, case create/delete, and read beacons for case/subject views — is written to an append-only audit log (who, from where, against which case, when), surfaced in the Admin tab's audit panel.

Deployment

Air-gapped (recommended)

The Windows installer (PyInstaller + Inno Setup) bundles the Python runtime, every dependency, and the static frontend into a single ~122 MB package. No network access is required at install time or runtime — this is the primary supported deployment for investigative units.

Server deployment

For a shared team deployment, run the FastAPI app behind a reverse proxy with HTTPS:

uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 4
  • Configure DATABASE_URL to point at PostgreSQL — SQLite is a single-writer fallback, not intended for concurrent multi-user production load.
  • Terminate TLS at a reverse proxy (Nginx/Caddy); set client_max_body_size high enough for large CSV uploads.
  • Change the bootstrap admin password immediately; set a non-default AUTH_SESSION_COOKIE_NAME.
  • Optional accelerators: Redis cache tier, Celery for background jobs, trigram/FTS5 search — all off by default, on by capability detection or explicit config.

Local AI (optional)

The AI Insights tab and report generation call a local Ollama instance at http://localhost:11434. If Ollama isn't running, those features degrade gracefully — every other tab works without it. No data leaves the machine when using local AI.

Scale & Performance

ARGUS is built to hold 1–5M+ record cases without freezing the browser or the database:

  • Bounded client mirror — the browser holds a capped, newest-first sample for live previews (timeline, correlation, mini-graph); authoritative analytics (dashboard, reports, inference, graph) are always computed server-side over the whole case.
  • Materialised analytics — an event-driven, versioned cache recomputes only what an append actually touches (incremental update), not a full rebuild every time. Dashboards and reports open instantly on a revisit.
  • Indexed IP matching — provider CIDR ranges are bucketed by first octet with precomputed integer bounds, turning a linear scan into a handful of integer comparisons — about 14 µs per row even with thousands of live-feed ranges loaded.
  • Server-built bounded graphs — the network graph endpoint returns a top-N heaviest-edge subgraph with full-coverage node weights, so the browser never assembles the whole graph in memory; large graphs switch to a canvas renderer.

FAQ

Does ARGUS require an internet connection?

No. Everything — ingestion, analysis, mapping, the inference engine, and (with Ollama installed) AI insights — runs fully offline. Map tiles from OpenStreetMap are the one optional online resource; without connectivity the map still functions, just without basemap imagery.

Which databases are supported?

PostgreSQL is the primary target; SQLite is an automatic fallback requiring zero setup, suitable for single-investigator use or development.

How is CDR/IPDR separation enforced?

Phone-number subjects (CDR) and IP subjects (IPDR) are never merged — distinct schemas, distinct graph components, distinct session-reconstruction paths. This is a deliberate design invariant enforced across the codebase and covered by tests, not just a UI convention.

Can I extend the service-attribution provider list?

Yes — edit attribution_data.json (add a provider with its CIDR ranges and services) and run gen_attribution_js.py to sync the frontend copy. For ASN-scale coverage, drop a CSV at data/asn_ranges.csv; longest-prefix matching means specific external ranges automatically win over the curated defaults.
